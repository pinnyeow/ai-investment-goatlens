# 0.2.0 public API migration

GOATlens 0.2.0 removed `data_status.normalized_ratios` and the
`provider_metric` evidence-input variant from the public analysis response.
These fields represented the retired provider-normalized ratio boundary and
have no compatibility replacement. Clients should use each metric's typed
`metric_evidence` availability, formula, and inputs instead.

`GET /api/price-history/{ticker}` also includes an explicit `adjusted_close`
number on every price point. This is an additive schema change: raw `open`,
`high`, `low`, and `close` remain available, while chart consumers should use
`adjusted_close` for split- and distribution-adjusted historical performance.

The unreleased `POST /api/analyze` contract now requires the canonical,
zero-padded SEC CIK at the top level and on every fundamental fact, metric-
evidence record, SEC evidence input, investor result, and comparison row. These
fields are required inside strict objects, so clients generated against an
earlier 0.2.0 prerelease schema must regenerate from OpenAPI. All redundant CIK
projections must exactly equal the top-level CIK. The SEC adapter obtains that
identity from the authoritative ticker map and rejects a Companyfacts payload
whose own CIK does not match before normalization. This establishes
lookup/payload agreement; it does not claim authenticity beyond SEC retrieval
and transport controls.

Standalone `AnalysisResponse.model_validate(...)` proves only internal response
self-consistency. It cannot establish that a coordinated public CIK projection is
the issuer requested by the route. The shipping `/api/analyze` boundary therefore
must call the trusted response validator with the request ticker plus the exact
request-scoped canonical ticker-map record (and its unkeyed SHA-256 content digest)
retained by the SEC adapter. That digest detects accidental content changes; it is
not a provider-authenticity or cryptographic-origin claim.

`data_status.market_data.split_events` is now a required typed projection of the
request-scoped Yahoo split-event leaves. The public verifier uses those dates,
the canonical SEC shares concept/unit/form, quote currency, and public ticker
class to recompute whether SEC-plus-price formulas are applicable. Unavailable
reason strings are descriptive only and cannot suppress otherwise reconstructable
metrics. Clients generated against an earlier prerelease schema must regenerate.
